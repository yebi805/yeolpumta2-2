# 🕹️ 열품타 픽셀 챌린지 — 처음부터 배포까지 따라 하기

우리 반 학생들이 **열품타 공부 시간을 입력** → **관리자(나)가 반 열품타 그룹 기록과 비교해 승인** → **코인 자동 지급** → **픽셀 캐릭터 꾸미기**를 하는 학급용 웹앱이야.
휴대폰·태블릿 인터넷 브라우저로 접속하면 되고, 설치할 앱은 없어.

> 표시 규칙
> 🙋 = **내가 직접 해야 하는 일**  ·  🤖 = **앱/DB가 자동으로 해 주는 일**

---

## 0. 한눈에 보기

| 학생 메뉴 | 하는 일 |
|---|---|
| 🏠 홈 | 내 캐릭터, 코인, 오늘 인증 상태, 반려 사유, 코인 변동 기록 |
| ✏️ 인증 | 날짜 선택 + 시간·분 입력 → 제출 (사진 없음) |
| 🧍 캐릭터 | 산 아이템 착용/해제 (미리보기 후 저장) |
| 🛍️ 상점 | 아이템 구매 (입혀 본 모습 미리보기) |
| 🏅 순위 | 승인된 공부 시간 합계 순위 |
| 🤝 퀘스트 | 반 전체 승인 시간 합계 vs 공동 목표 |

**관리자 화면**은 주소 끝에 `?admin` 을 붙여서 들어가. (예: `https://우리반앱.streamlit.app/?admin`)
학생 화면에는 관리자 메뉴가 아예 안 보여.

### 보상 규칙 (기본값)
| 조건 (승인된 시간 기준) | 코인 |
|---|---|
| 하루 인증 승인 | 10 |
| 1시간 이상 | +10 |
| 2시간 이상 | +10 |
| 3시간 이상 | +15 |

예) 3시간 12분 → 10+10+10+15 = **45코인** / 59분 → **10코인** / 1시간 정각 → **20코인**

## 1. 파일 구성 (각 파일이 하는 일)

| 파일 | 역할 | GitHub에 올려? |
|---|---|---|
| `app.py` | 화면 전체 (학생 화면 + 관리자 화면). 맨 위에 **보상 규칙·아이템 목록** 설정이 모여 있음 | ✅ |
| `schema.sql` | DB 표 + 안전한 DB 함수 + 보안 잠금. Supabase에서 **한 번 실행** | ✅ |
| `requirements.txt` | 필요한 파이썬 패키지 목록 (Streamlit Cloud가 자동 설치) | ✅ |
| `.streamlit/config.toml` | 화면 색상, 오류 내용 숨기기 설정 (비밀 정보 없음) | ✅ |
| `.gitignore` | 비밀 파일이 GitHub에 올라가지 않게 막는 목록 | ✅ |
| `secrets.toml.example` | Secrets 입력 예시 (진짜 값 없음) | ✅ |
| `README.md` | 지금 이 설명서 | ✅ |
| `.streamlit/secrets.toml` | (로컬에서 테스트할 때만) 진짜 비밀번호·키 | ❌ **절대 안 됨** |

### 이전 버전(ChatGPT와 만든 버전)에서 바뀐 점
- 사진 업로드 삭제 → **시간·분 직접 입력** (Storage 설정 필요 없음)
- 제출 시간 검사: 0분 불가, 하루 최대 16시간, **한국 날짜 기준** 오늘 포함 최근 3일 (미래 날짜 불가)
  - 예전엔 서버 시간(UTC) 기준이라 아침 9시 전엔 날짜가 하루 밀리는 문제가 있었음
- 승인·보상 지급, 구매를 **DB 함수 하나에서 한 번에 처리** (중간에 오류 나면 전부 취소)
- 반려 사유 기록 + 반려된 기록도 지우지 않고 남김 → 다시 제출 가능
- 관리자 화면: 학생 입력 시간, 예상 출석/시간/총 코인 표시, **시간을 고쳐서 승인** 가능
- 보안 강화: DB 잠금(RLS), 로그인 5회 실패 시 10분 잠금, 쉬운 PIN 차단, 별명 특수문자 차단
- 반 공동 퀘스트: "목표 달성 인원 수" → **반 전체 승인 시간 합계 vs 목표**
- 메뉴 6개 + 픽셀 캐릭터 그림 새로 그림 (아이템을 실제로 입혀서 보여 줌)

## 2. 1단계: Supabase(데이터베이스) 만들기  🙋

1. https://supabase.com 접속 → **Start your project** → GitHub 계정으로 로그인
2. **New project** 클릭
   - Name: `yeolpumta-pixel` (아무거나)
   - Database Password: 자동 생성 버튼 눌러도 됨 (이 앱에서는 안 씀, 그래도 메모해 두기)
   - Region: **Northeast Asia (Seoul)** 추천 (가까울수록 빠름)
   - **Create new project** → 1~2분 기다리기
3. 왼쪽 메뉴 **SQL Editor** → **New query**
4. `schema.sql` 파일을 메모장으로 열어서 **전체 복사(Ctrl+A → Ctrl+C)** → SQL Editor에 붙여 넣기
5. 오른쪽 아래 **Run** 클릭
   - ✅ 성공하면 `Success. No rows returned` 가 보여
   - 경고창(“destructive operation” 같은 문구)이 뜨면 **Run this query** 눌러도 돼. 기존 데이터를 지우는 명령은 없어.
6. 🤖 자동으로 만들어지는 것: 표 7개, DB 함수 20개, 보안 잠금(RLS)

### 키 복사하기 🙋
왼쪽 아래 ⚙️ **Project Settings** → **API Keys** (또는 Data API) 메뉴에서:
- **Project URL**: `https://xxxx.supabase.co` 형태 → 메모
- **Secret key**: `sb_secret_...` 로 시작하는 키 → 메모
  - 화면에 `service_role` (Legacy) 키만 보이면 그걸 써도 돼.
  - ⚠️ `anon` / `publishable` 키는 **아니야**. 그 키로는 DB가 잠겨 있어서 앱이 동작하지 않아. (일부러 그렇게 잠근 것)

> ⚠️ Secret key = **DB 마스터키**. 카톡·GitHub·스크린샷 어디에도 올리면 안 돼.

## 3. 2단계: GitHub에 파일 올리기  🙋

1. https://github.com → 오른쪽 위 **+** → **New repository**
   - 이름: `yeolpumta-pixel`
   - **Private** 선택 추천 (코드에 비밀은 없지만, 굳이 공개할 필요 없음)
   - **Create repository**
2. **uploading an existing file** 링크 클릭 → 아래 파일 끌어다 놓기
   - `app.py`, `schema.sql`, `requirements.txt`, `README.md`, `.gitignore`, `secrets.toml.example`
   - **Commit changes**
3. `.streamlit/config.toml` 은 폴더라서 따로 만들어야 해:
   - 저장소 화면에서 **Add file → Create new file**
   - 파일 이름 칸에 `.streamlit/config.toml` 이라고 입력 (슬래시 `/` 를 치면 폴더가 자동으로 생겨)
   - 내용 칸에 `config.toml` 파일 내용을 그대로 붙여 넣기 → **Commit changes**
   - (윈도우에서 `.gitignore` 처럼 점으로 시작하는 파일이 안 보이면, 같은 방법으로 Create new file 해서 내용 붙여 넣기)

✅ 확인: 저장소 파일 목록에 `secrets.toml` 이라는 진짜 비밀 파일이 **없어야** 정상!

## 4. 3단계: Streamlit Cloud 배포 + Secrets 입력  🙋

1. https://share.streamlit.io → GitHub 계정으로 로그인
2. **Create app** → **Deploy a public app from GitHub** (Yup, I have an app)
3. 입력:
   - Repository: `내아이디/yeolpumta-pixel`
   - Branch: `main`
   - Main file path: `app.py`
   - App URL: 원하는 주소 (예: `our-class-study`)
4. **Advanced settings** 클릭
   - Python version: **3.12** (또는 기본값)
   - **Secrets** 칸에 아래를 붙여 넣고 값을 바꾸기 (`secrets.toml.example` 참고)

```toml
SUPABASE_URL = "https://xxxx.supabase.co"
SUPABASE_SECRET_KEY = "sb_secret_xxxxxxxx"
CLASS_CODE = "반친구들에게만_알려줄_참여코드"
ADMIN_PASSWORD = "나만아는_12자이상_관리자비밀번호"
```

   - `CLASS_CODE`: 가입할 때 필요한 반 코드. **반 단톡방에만** 공유
   - `ADMIN_PASSWORD`: 최소 8자, **12자 이상 추천**. 아무에게도 알려 주지 않기
5. **Deploy** → 2~3분 기다리면 앱 주소가 생겨! 🤖 패키지 설치는 자동

> 나중에 Secrets를 바꾸려면: 내 앱 오른쪽 아래 **Manage app** → ⋮ → **Settings → Secrets**

### 화면에 이런 메시지가 뜨면
| 메시지 | 원인 / 해결 |
|---|---|
| "데이터베이스 연결 정보가 없어요" | Secrets에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY` 가 없음 → 4번 다시 |
| "Supabase 에 연결하지 못했어요" | ① URL·키 오타 ② anon 키를 넣음 ③ `schema.sql` 실행 안 함 → Manage app 로그 확인 |
| "관리자가 아직 반 참여 코드를 설정하지 않았어" | Secrets에 `CLASS_CODE` 없음 |
| "Secrets 에 ADMIN_PASSWORD(8자 이상)를 먼저 설정해 줘" | 관리자 비밀번호가 없거나 너무 짧음 |

## 6. 매일 운영 루틴 (관리자)  🙋

1. 정해진 시간에 `앱주소/?admin` 접속 → 관리자 비밀번호 입력
2. **📋 검토 대기** 탭에서 한 명씩:
   - 반 열품타 그룹 기록과 학생 입력 시간 비교
   - 같으면 **✅ 승인** → 🤖 코인 자동 지급
   - 조금 다르면 **승인 시간/분을 고친 뒤 승인** → 🤖 고친 시간으로 코인 계산
   - 많이 다르거나 거짓이면 **반려 사유 입력 → ↩️ 반려** → 학생이 다시 제출 가능
3. 끝나면 **관리자 로그아웃**

> 승인 버튼을 실수로 두 번 눌러도, 인터넷이 끊겨도, 새로고침해도 **같은 보상은 절대 두 번 지급되지 않아.** (DB가 막음)
> "결과를 확인하지 못했어요" 메시지가 뜨면 새로고침해서 상태만 확인하면 돼.

## 7. 규칙 바꾸는 법  🙋

- **보상 코인**: `app.py` 맨 위 `REWARD_RULES` 숫자만 고치고 GitHub에 저장 → 🤖 1분 안에 앱 자동 재시작
  - 이미 지급된 코인은 그대로, **이후 승인부터** 새 규칙 적용
- **아이템 추가**: `app.py` 의 `ITEMS` 에 한 줄 추가 (그림은 `ITEM_SPRITES` 에 도트 추가, 없으면 그림 변화 없이 보유만 됨)
  - 이미 있는 아이템의 `id` 는 바꾸지 않기 (학생 보유 기록이 id로 저장됨)
- **반 공동 목표 시간**: 관리자 화면 → ⚙️ 반 설정 → 목표 저장 (코드 수정 필요 없음)
- **하루 최대 시간(16시간) / 제출 가능 기간(3일)**: `app.py` 와 `schema.sql` 의 `submit_study` 함수 **두 곳 모두** 바꿔야 함
  (`schema.sql` 수정 후 SQL Editor에서 그 함수 부분만 다시 실행)

## 8. 자동으로 막아 주는 것들 (어떻게 안전한지)  🤖

| 위험 | 막는 방법 |
|---|---|
| 같은 날 출석 보상 2번 | 코인 장부에 `(학생, attendance:날짜)` 고유 제약 → DB가 두 번째 입력 거부 |
| 같은 시간 달성 보상 2번 | `(학생, study:날짜:60)` 같은 고유 키 |
| 승인 버튼 2번 / 동시에 여러 번 | 승인 함수가 그 제출을 잠그고(FOR UPDATE) "검토 대기"일 때만 처리. 동시에 10번 눌러도 1번만 처리됨을 테스트로 확인 |
| 승인은 됐는데 코인 지급 중 오류 | 승인+지급이 한 트랜잭션 → 오류 시 **둘 다 취소**되어 다시 승인 가능 |
| 같은 날 여러 번 제출 | "검토 중/승인" 기록은 날짜당 1개만 허용하는 DB 인덱스 |
| 잔액보다 비싼 구매 / 연타 구매 | 구매 함수가 학생을 잠그고 잔액 확인 → 지급·차감을 한 번에. 동시에 5번 눌러도 1번만 구매됨을 테스트로 확인 |
| 코인 기록 조작 | 장부는 추가만 가능, 수정 불가(트리거) |
| 다른 사람이 DB 직접 조회 | 모든 표 RLS 잠금 + anon 권한 회수. 앱 서버(secret key)만 접근 |
| PIN 유출 | PBKDF2-SHA256 60만 회 해시 + 학생별 랜덤 salt (원래 PIN은 저장 안 함) |
| PIN 마구 찍기 | 5번 틀리면 10분 잠금 (관리자 로그인도 동일) |
| 별명에 HTML 넣어 화면 조작 | 별명은 한글/영문/숫자/_ 만 허용 + 화면 출력 시 이스케이프 |
| 오류 화면에 내부 정보 노출 | `showErrorDetails = "none"` → 학생에겐 일반 메시지만 |

## 9. 배포 전 보안·개인정보 체크리스트  🙋

- [ ] GitHub 저장소에 `secrets.toml` 파일이나 키가 **없다** (커밋 기록 포함)
- [ ] Streamlit Secrets에 넣은 키가 `anon`/`publishable` 이 아니라 **secret(service_role)** 키다
- [ ] `ADMIN_PASSWORD` 12자 이상, 반 참여 코드와 **다른** 값이다
- [ ] 반 참여 코드는 반 단톡방에만 공유했다 (공개 게시판 ❌)
- [ ] 학생들에게 안내: **실명·학번·전화번호를 별명으로 쓰지 않기**, PIN을 친구와 공유하지 않기, 다른 사이트와 같은 비밀번호 쓰지 않기
- [ ] 이 앱은 학교 공식 시스템이 아니라 **반 자율 활동**이라는 점을 담임 선생님께 미리 말씀드렸다 (권장)
- [ ] 테스트 데이터를 지웠다 (5단계 SQL)
- [ ] 관리자 주소(`?admin`)를 반 친구들에게 알리지 않았다 (알아도 비밀번호 없으면 못 들어오지만, 굳이 알릴 필요 없음)
- [ ] 활동이 끝나면 Supabase 프로젝트를 삭제할지 정해 두었다 (Project Settings → General → Delete project)

**수집하는 정보**: 별명, PIN 해시, 날짜별 공부 시간, 코인/아이템 기록 — 끝.
실명·전화번호·이메일·사진은 받지 않아.

## 10. 알아 둘 한계 (솔직하게)

- **새로고침하면 로그아웃**돼. (로그인 정보를 브라우저에 저장하지 않는 방식. 별명+PIN으로 다시 로그인)
- 열품타 앱과 **자동 연동되지 않아.** 관리자가 눈으로 대조하는 방식이야.
- **PIN을 잊어버리면** 학생이 직접 바꿀 방법이 없어. 새 별명으로 다시 가입하거나, 관리자가 Supabase에서 계정을 지워 줘야 해 (코인도 같이 사라짐).
- 잠금 풀어 주기 (SQL Editor): `delete from public.login_guard where key = 'p:별명소문자';` / 관리자 잠금은 `key = 'admin'`
- 하루 최대 시간·제출 기간 값이 `app.py`와 `schema.sql` 두 곳에 있어 (DB가 최종 검사).
- 무료 플랜 특성 (정책은 바뀔 수 있으니 각 사이트에서 확인 필요):
  - Streamlit Cloud 앱은 한동안 접속이 없으면 잠들어서, 첫 접속 때 깨우는 버튼을 눌러야 할 수 있어.
  - Supabase 무료 프로젝트는 오래 사용하지 않으면 일시정지될 수 있어. 대시보드에서 다시 켜면 돼.
- Supabase의 새 키(`sb_secret_...`)는 Supabase가 기존 `service_role` 키를 대체하려고 도입한 방식이야. 이 앱은 둘 다 받을 수 있게 만들었지만, 실제 Supabase 서버와는 아직 테스트하지 못했어 (테스트는 로컬 PostgreSQL로 함). 연결이 안 되면 Legacy `service_role` 키로 바꿔 넣어 봐.
